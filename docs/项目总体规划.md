## 一、项目概述

### 1.1 项目愿景

**老黄牛**是一个通用型 AI 工作助手（Agent）。名字取自"老黄牛"——勤勤恳恳、任劳任怨、值得托付。

我们的目标，是让老黄牛成为你在电脑上的**数字员工**：凡是能用"人机交互"在电脑上完成的日常工作，它都能替你完成，或在你监督下协助完成。包括但不限于：

- 写代码、改 Bug、重构、跑测试
- 处理文件与项目（整理、转换、脚手架）
- 联网检索、抓取、汇总信息并产出报告
- 办公自动化（表格、文档、邮件、日程）
- 媒体处理（视频剪辑、字幕、图片处理）

一句话概括：**"把你能在电脑上干的活，交给老黄牛。"**

### 1.2 项目目标

| 编号 | 目标 | 说明 |
|------|------|------|
| G1 | 可靠地写代码 | 能理解需求、生成/修改代码、运行并验证结果 |
| G2 | 能干各类"活" | 覆盖文件、代码、办公、媒体等电脑端日常任务 |
| G3 | 能找并整理信息 | 联网检索 + 抓取 + 多来源汇总 + 生成摘要/报告 |
| G4 | 交互体验逐步升级 | 命令行（CLI）→ 文本界面（Web）→ 语音交互 |
| G5 | 多模型可切换 | 按任务选择最合适的 LLM，支持降级与成本优化 |
| G6 | 安全可控 | 分级权限、危险操作确认、完整审计日志、沙箱执行 |

### 1.3 核心价值

- **通用性**：不局限于单一场景，覆盖"电脑上的日常工作"这一大类。
- **可解释**：每一步"思考—行动—观察"都可见，用户可审计。
- **可定制**：工具即插件，新能力可低成本扩展。
- **私有优先**：默认本地运行，数据与密钥尽量不出本机。

### 1.4 非目标（Scope 边界）

为避免范围失控，以下明确**不在**本项目范围内：

- 需要操作物理世界的任务（如控制实体设备、IoT）。
- 追求"通用人工智能（AGI）"——我们聚焦"电脑上的日常工作"。
- 多租户 SaaS / 商业化运营平台（初期定位为**个人/小团队的本地助手**）。
- 替代专业设计/剪辑软件的全部能力（视频制作定位为"自动化剪辑 + 字幕 + 简单合成"，而非替代专业创作工具）。

### 1.5 用户画像

- **主要用户**：开发者、技术爱好者、需要自动化办公的个人与小团队。
- **典型使用方式**：坐在电脑前，用自然语言（打字或说话）下达任务，老黄牛在后台执行并反馈结果。
- **使用环境**：Windows（当前开发机），后续兼容 macOS / Linux。

## 二、核心能力

老黄牛的能力模型可概括为"**三大核心能力 + 一条交互演进路径**"。

### 2.1 写代码（Code Engineering）

> 让老黄牛像一个靠谱的后端/全栈工程师一样工作。

- 理解自然语言需求，生成可运行代码（Python / JS / TS / Shell 等）。
- 定位并修复 Bug：读取代码 → 定位问题 → 修改 → 运行验证。
- 重构与代码审查：按规范重构、发现潜在缺陷并给出建议。
- 运行与验证：执行脚本、跑单元测试、解读报错并迭代修复。
- 版本管理：`git` 操作（查看状态、提交、diff、分支）。
- 项目脚手架：按模板生成项目结构、配置依赖。

**验收示例**：
- "帮我写一个解析 CSV 并输出统计报表的 Python 脚本" → 生成、运行、给出结果。
- "这个函数为什么超时？帮我修一下" → 定位、修复、跑测试通过。

### 2.2 干活（General Work）

> 覆盖"所有人类能在电脑上完成"的日常工作，按领域划分：

| 领域 | 能力 |
|------|------|
| 文件与项目操作 | 读写、整理、批量重命名、格式转换、目录遍历、项目脚手架 |
| 代码工程任务 | 见 2.1 |
| 信息检索与整理 | 联网搜索、网页抓取、多来源汇总、生成摘要/报告 |
| 日常办公自动化 | 处理 Excel / Word / PDF、整理邮件、日程与提醒、数据清洗 |
| 信息收集 | 定向抓取、监控、定时采集、结构化入库 |
| 媒体制作 | 视频合成/剪辑、字幕生成、图片处理、音频转写 |
| 系统操作 | 执行受控的命令行任务（在沙箱/权限约束下） |

**关键原则**：能力以"**工具（Tool）**"形式插件化提供，新增一类活 = 新增一组工具，无需改动核心引擎。

### 2.3 找信息（Information Retrieval）

- **联网搜索**：调用搜索引擎 API（Bing / Brave / SerpAPI 等），获取实时信息。
- **网页抓取**：读取指定 URL，提取正文（含动态页面渲染，可选 Playwright）。
- **多来源汇总**：对多个结果做去重、排序、交叉验证。
- **结构化产出**：生成摘要、对比表、Markdown 报告，并可落盘保存。
- **知识沉淀**：重要结论可写入长期记忆（向量库），供后续问答复用（RAG）。

**验收示例**：
- "帮我查一下 2026 年 Python 3.13 的主要新特性，整理成一页摘要" → 检索 + 汇总 + 输出。
- "对比 A、B、C 三款产品的价格与参数" → 抓取 + 生成对比表。

### 2.4 交互演进（Interaction）

交互是用户体验的入口，按"从简到繁、从文字到声音"分阶段演进：

| 阶段 | 形态 | 说明 |
|------|------|------|
| Phase 1 | **命令行（CLI）** | 终端里的对话式 TUI，最轻量、最快落地 |
| Phase 3 | **文本界面（Web）** | 浏览器里的聊天式界面，支持富文本、文件预览、任务看板 |
| Phase 3/4 | **语音交互** | 语音输入（ASR）+ 语音播报（TTS），可"免手操作" |

> 演进的关键：三种界面共享**同一套 Agent 内核与工具系统**，界面只是"外壳"，能力不因界面而重复实现。

## 三、技术选型

### 3.1 开发语言：Python 3.11+（推荐）

**选择 Python 的理由**：

1. **AI 生态最完整**：主流 LLM SDK（OpenAI / Anthropic / Gemini / OpenRouter）均以 Python 为一等公民。
2. **"干活"场景库最全**：办公（openpyxl、python-docx、pdfplumber、PyMuPDF）、爬虫（httpx、BeautifulSoup、Playwright）、媒体（MoviePy、ffmpeg、Pillow）、语音（faster-whisper、pyttsx3）等，Python 都有成熟方案。
3. **跨平台**：Windows / macOS / Linux 一致运行，契合"个人本地助手"定位。
4. **开发效率高**：动态类型 + 简洁语法，适合快速迭代 Agent 与工具插件。

**权衡**：Python 在超高性能/并发场景弱于 C++/Go，但本项目的瓶颈在 LLM 调用与 I/O（网络、磁盘），而非 CPU 密集计算，Python 完全够用。

### 3.2 大模型（LLM）：多模型可切换

**策略**：不绑定单一供应商，通过统一的抽象层支持多家，并**按任务路由**到最合适的模型。

| 模型供应商 | 代表模型 | 擅长场景 |
|------------|----------|----------|
| OpenAI | GPT-4o / o 系列 | 综合能力强、代码好，默认主力 |
| Anthropic | Claude 系列 | 长上下文、推理与代码质量高 |
| Google | Gemini 系列 | 多模态（图文）、长上下文 |
| OpenRouter | 聚合多家 | 一个 Key 用多家，便于切换与成本优化 |

**实现要点**：
- 用统一网关（如 `litellm` 或自研薄封装）屏蔽各家 SDK 差异。
- 配置化"任务 → 模型"路由规则，例如：代码任务优先 GPT-4o / Claude，多模态用 Gemini，低成本批量任务用更小的模型。
- 支持**降级**：主模型失败/超时时自动切换备用模型。
- 支持**密钥与端点**从 `.env` / 配置文件注入，不落库、不硬编码。

### 3.3 核心 Agent 框架

**推荐**：自研一个**轻量 ReAct（Reason + Act）引擎**作为内核，而不是直接套用重型框架。

理由：
- 对"思考 → 调用工具 → 观察结果 → 再思考"的循环拥有完全控制权，便于实现**安全门、审计、可中断、可回放**。
- 依赖少、行为可预测、便于调试与排障。
- 后续若需要复杂的多步骤/多智能体编排，可在其上引入 **LangGraph** 等编排库，核心工具与记忆层可复用。

**备选**：若希望快速起步，可评估 `LangGraph` / `CrewAI`，但建议以自研轻量内核为主、编排库为辅。

### 3.4 各场景技术栈一览

| 场景 | 推荐库/工具 | 备注 |
|------|-------------|------|
| LLM 统一网关 | `litellm` 或自研封装 | 多供应商 + 路由 + 降级 |
| CLI 界面 | `rich` + `textual` + `prompt_toolkit` | 终端 TUI、流式输出、命令补全 |
| 配置管理 | `pydantic` + `pydantic-settings` + YAML | 强类型配置、校验 |
| 联网搜索 | Bing / Brave / SerpAPI（HTTP） | 需 API Key |
| 网页抓取 | `httpx` + `BeautifulSoup4`；动态页用 `Playwright` | 静态优先，必要时渲染 |
| Excel | `openpyxl` | 读写 .xlsx |
| Word | `python-docx` | 读写 .docx |
| PDF | `pdfplumber` / `PyMuPDF` | 文本抽取、解析 |
| 视频 | `MoviePy` + `ffmpeg` | 合成、剪辑、字幕、转码 |
| 图片 | `Pillow` | 缩放、裁剪、水印、格式转换 |
| 语音识别(ASR) | `faster-whisper` | 本地/离线可用，准确度高 |
| 语音合成(TTS) | `edge-tts` / `piper` | 中文效果较好 |
| 端点检测(VAD) | `silero-vad` | 语音交互时判断"说完了没" |
| 向量库(RAG) | `chromadb` / `lancedb`（本地） | 长期记忆、知识检索 |
| 持久化 | `SQLite`（默认）/ `Supabase`（可选云端） | 会话、记忆、任务记录 |
| Web 后端(Phase 3) | `FastAPI` + `WebSocket` | 流式对话、任务推送 |
| Web 前端(Phase 3) | `React` + `Vite` | 聊天界面、文件预览、任务看板 |
| 沙箱执行 | `subprocess` 约束 + 可选 `Docker` | 代码/命令安全执行 |
| 包管理 | `pyproject.toml`（PEP 621）+ `uv` 或 `poetry` | 依赖与虚拟环境 |

### 3.5 选型对比与结论

| 维度 | 方案 A：Python（推荐） | 方案 B：Node.js/TypeScript |
|------|------------------------|----------------------------|
| AI/LLM 生态 | ★★★★★ | ★★★★ |
| 办公/媒体/语音库 | ★★★★★ | ★★★ |
| Web/语音前端 | ★★★（需另写前端） | ★★★★★ |
| 跨平台 | ★★★★ | ★★★★ |
| 上手迭代速度 | ★★★★★ | ★★★★ |

**结论**：以 **Python 为核心**承载 Agent 内核与全部工具能力；Phase 3 的 Web 前端可用 React/TypeScript 独立实现，与 Python 后端通过 HTTP/WebSocket 通信。这样既发挥 Python 在"干活"上的优势，又不牺牲前端体验。

## 四、系统架构

### 4.1 架构总览

老黄牛采用"**内核 + 工具 + 记忆 + 界面 + 安全**"的分层架构。所有界面（CLI/Web/语音）都调用同一个内核，能力不因界面而重复。

```
┌──────────────────────────────────────────────────────────────┐
│                       交互层 (Interface)                       │
│   CLI (Phase 1)   │   Web 文本 (Phase 3)   │   语音 (Phase 3+)  │
└───────────────┬──────────────────┬──────────────────┬──────────┘
                │        统一的会话/任务协议 (JSON)      │
┌───────────────▼──────────────────▼──────────────────▼──────────┐
│                     Agent 内核 (Core)                           │
│  ┌────────────┐  ┌────────────┐  ┌──────────────────────────┐  │
│  │ ReAct 引擎  │  │ 任务规划器  │  │  会话/上下文管理          │  │
│  └─────┬──────┘  └────────────┘  └──────────────────────────┘  │
│        │  思考 → 选工具 → 行动 → 观察 → 循环/收尾                  │
└────────┼───────────────────────────────────────────────────────┘
         │
   ┌─────▼─────────────────────────────────────────────────────┐
   │              LLM Provider 抽象层 (多模型可切换)             │
   │   OpenAI / Anthropic / Gemini / OpenRouter  + 路由 + 降级   │
   └─────────────────────────────────────────────────────────────┘
         │
   ┌─────▼─────────────────────────────────────────────────────┐
   │                     工具系统 (Tool System)                  │
   │  文件 │ 代码 │ Web │ 办公 │ 媒体 │ 系统  （插件式注册表）     │
   └─────────────────────────────────────────────────────────────┘
         │
   ┌─────▼─────────────┐        ┌──────────────────────────────┐
   │   记忆系统 (Memory) │        │   安全与权限 (Safety)         │
   │ 短期上下文 + 长期RAG │        │  分级权限 + 沙箱 + 审计日志    │
   └─────────────────────┘        └──────────────────────────────┘
```

### 4.2 核心 Agent Loop（ReAct）

内核主循环遵循 **ReAct（Reason + Act）** 模式：

```
用户输入
   │
   ▼
[1 规划] 拆解目标，确定需要哪些工具、步骤顺序
   │
   ▼
[2 循环] ┌────────────────────────────────────────┐
         │  LLM 思考(Reason)                        │
         │      → 决定调用哪个工具(Act)              │
         │      → 安全门校验(是否需确认/沙箱)        │
         │      → 执行工具，得到观察结果(Observe)    │
         │      → 结果拼回上下文，继续思考           │
         │      → 直到达成目标或触发停止条件         │
         └────────────────────────────────────────┘
   │
   ▼
[3 收尾] 汇总结果，向用户输出结论/产物（文件、报告、代码等）
```

**关键设计**：
- **可中断**：用户随时可 `Esc` 中断当前循环。
- **可审计**：每轮"思考/工具/参数/结果"都记录到会话日志，事后可回放。
- **停止条件**：达成目标 / 达到最大步数 / 连续失败 / 用户中断 / 预算（token/时间）超限。
- **失败回退**：某工具失败时，LLM 可换策略重试，而不是直接报错终止。

### 4.3 LLM Provider 抽象层

统一接口（伪代码）：

```python
class LLMProvider(Protocol):
    def chat(self, messages, tools, model, **kwargs) -> LLMResponse: ...
    def stream(self, messages, tools, model) -> Iterator[Chunk]: ...

# 统一网关：屏蔽 OpenAI/Anthropic/Gemini/OpenRouter 差异
def get_provider(name: str) -> LLMProvider: ...

# 路由：按任务类型选择模型
def route_model(task_type: str) -> str:
    return config.routing.get(task_type, config.default_model)
```

- **路由表**（示例，配置化）：
  - `code` → `gpt-4o`（或 `claude`）
  - `long_context` / `reasoning` → `claude` / `gemini`
  - `multimodal` → `gemini`
  - `batch_low_cost` → 更小/更便宜的模型
- **降级链**：`gpt-4o → claude → gemini`，主模型不可用时自动顺延。
- **流式输出**：所有 Provider 统一支持 stream，界面层可实时展示。

### 4.4 工具系统（Tool System）

**设计原则**：工具即插件。每个工具是一段带**结构化描述**（名称、说明、参数 schema）的函数，注册进统一的 `ToolRegistry`，LLM 依据描述自行决定何时调用。

**工具的统一契约**：

```python
@dataclass
class Tool:
    name: str
    description: str
    parameters: dict          # JSON Schema
    risk: RiskLevel          # read / write / execute / dangerous
    func: Callable
```

**内置工具分组**（示例，非穷尽）：

| 分组 | 工具示例 | 风险级别 |
|------|----------|----------|
| 文件 | `file_read` / `file_write` / `file_edit` / `list_dir` / `glob` / `grep` / `move` / `copy` / `delete` | read / write / delete=dangerous |
| 代码 | `run_python` / `run_shell` / `run_tests` / `git_*` | execute |
| Web | `web_search` / `web_fetch` / `web_scrape` | read |
| 办公 | `excel_read` / `excel_write` / `word_write` / `pdf_extract` / `email_*` | read / write |
| 媒体 | `video_compose` / `image_process` / `audio_transcribe` | write |
| 系统 | `run_command`（沙箱） / `env_get` | execute / dangerous |

**扩展性**：
- 支持 **MCP（Model Context Protocol）**，可接入第三方工具服务器，进一步扩展能力。
- 用户可放置自定义工具（约定目录 + 注册），无需改核心。

### 4.5 记忆系统（Memory）

分为**短期**与**长期**两层：

**短期记忆（会话上下文）**
- 保存当前会话的消息与工具调用历史。
- 超长时做**滚动窗口 + 摘要压缩**，防止超出上下文窗口。

**长期记忆（跨会话）**
- **事实/偏好**：用户的习惯、常用路径、项目约定等，存 `SQLite`（或 Supabase）。
- **知识（RAG）**：把重要文档/检索结论切片后存入本地向量库（chromadb / lancedb），问答时先检索再作答。
- **任务历史**：记录每次任务的输入、步骤、产物，便于复盘与复用。

> 记忆系统是"老黄牛越用越懂你"的关键，Phase 2 起逐步完善。

### 4.6 界面层（Interface Layer）

三种界面共享同一"会话/任务协议"（JSON 消息流），内核与工具不感知具体界面：

- **CLI（Phase 1）**：`textual` 构建 TUI，支持流式输出、工具调用可视化、命令补全、`Esc` 中断。
- **Web 文本（Phase 3）**：`FastAPI` + WebSocket 提供流式接口；React 前端做聊天、文件预览、任务看板。
- **语音（Phase 3+）**：麦克风采集 → VAD 断句 → ASR 转文本 → 走同一内核 → TTS 播报；支持"免手操作"。

### 4.7 安全与权限（Safety）

**分级权限模型**：

| 风险级别 | 示例 | 默认行为 |
|----------|------|----------|
| `read` | 读文件、搜索、抓取 | 自动执行 |
| `write` | 写文件、生成产物 | 提示后执行（可配置为自动） |
| `execute` | 跑代码、跑命令 | 需用户确认 |
| `dangerous` | 删除、覆盖、批量改、执行未知命令 | 强确认 + 二次校验 + 记录审计 |

**配套机制**：
- **沙箱执行**：代码/命令在受限环境运行（`subprocess` 资源限制，可选 `Docker` 隔离）。
- **路径白名单**：限定可操作的工作目录，防止越权访问敏感路径。
- **审计日志**：所有工具调用（含参数、结果、耗时）落盘，可查询、可回放。
- **可中断**：任意危险操作前给确认，运行中可 `Esc` 停止。
- **密钥安全**：API Key 只从 `.env`/系统读取，绝不写入日志或产物。

## 五、功能模块详解

> 每个模块给出：能力、依赖工具、风险级别、验收标准。便于拆分任务与验收。

### 5.1 代码工程模块

- **能力**：生成代码、修 Bug、重构、跑测试、git 操作、脚手架。
- **工具**：`file_*`、`run_python`、`run_tests`、`run_shell`、`git_*`、`web_search`（查文档）。
- **风险**：write / execute。
- **验收标准**：
  - 能根据一句话需求生成可运行的脚本并自测通过。
  - 能定位一个给定 Bug 并修复、测试通过。
  - 修 Bug 过程可查看"思考—改码—跑测试—通过"的完整链路。

### 5.2 文件与项目操作模块

- **能力**：读写/编辑/移动/重命名、批量处理、格式转换、目录遍历、脚手架生成。
- **工具**：`file_read` / `file_write` / `file_edit` / `list_dir` / `glob` / `grep` / `move` / `copy` / `delete`。
- **风险**：read / write / delete（dangerous）。
- **验收标准**：
  - 能按描述批量重命名/整理一个目录。
  - 能在白名单目录内安全增删改文件，越界操作被拦截。
  - 删除等危险操作触发强确认。

### 5.3 信息检索与整理模块

- **能力**：联网搜索、网页抓取、多来源汇总、生成摘要/报告、落盘保存。
- **工具**：`web_search` / `web_fetch` / `web_scrape`（可选 Playwright 渲染）、`file_write`（存报告）。
- **风险**：read / write（存产物）。
- **验收标准**：
  - 能对一个问题给出带来源引用的答案。
  - 能把多个来源整理成一页 Markdown 摘要或对比表。
  - 结果可保存为文件并给出路径。

### 5.4 办公自动化模块

- **能力**：读写 Excel / Word / PDF、数据清洗、邮件整理、日程与提醒。
- **工具**：`excel_*`、`word_*`、`pdf_extract`、`email_*`（按需接入）、`schedule_*`（可选）。
- **风险**：read / write。
- **验收标准**：
  - 能把一份杂乱 CSV/Excel 清洗成规整表格并输出新文件。
  - 能从 PDF 抽取结构化文本。
  - 能按模板生成 Word 报告。

### 5.5 信息收集模块

- **能力**：定向抓取、定时采集、结构化入库、变化监控。
- **工具**：`web_*`、`excel_write` / 数据库写入、`schedule_*`。
- **风险**：read / write。
- **验收标准**：
  - 能按规则从指定来源持续采集并结构化存储。
  - 能检测数据变化并提示。

### 5.6 媒体制作模块

- **能力**：视频合成/简单剪辑、字幕生成、图片处理、音频转写。
- **工具**：`video_compose`（MoviePy+ffmpeg）、`image_process`（Pillow）、`audio_transcribe`（faster-whisper）。
- **风险**：write（生成产物）。
- **验收标准**：
  - 能把若干片段 + 字幕合成一个视频。
  - 能给音频生成文字稿（转写）。
  - 能对图片做缩放/裁剪/加水印等处理。

### 5.7 系统操作模块

- **能力**：在权限约束下执行受控的命令行任务（安装依赖、跑构建等）。
- **工具**：`run_command`（沙箱）、`env_get`。
- **风险**：execute / dangerous。
- **验收标准**：
  - 能执行白名单内的命令并回传结果。
  - 危险命令（删除、系统级修改）被强确认或拦截。
  - 所有执行均有审计日志。

## 六、交互设计

### 6.1 命令行界面（CLI）— Phase 1 首选

**目标**：在终端里就能"对话式"地使唤老黄牛，体验接近聊天机器人。

**核心体验**：
- 启动后进入对话模式，输入自然语言任务，老黄牛流式输出"思考 + 行动 + 结果"。
- 实时展示每一步调用了哪个工具、参数是什么、结果如何（可折叠/展开）。
- 危险操作弹出确认（`y/n`）。
- `Esc` 随时中断；`/help`、`/model`、`/clear`、`/history` 等斜杠命令。
- 会话历史可保存、可继续（`resume`）。

**常用斜杠命令（示例）**：

| 命令 | 作用 |
|------|------|
| `/help` | 查看帮助 |
| `/model` | 查看/切换当前模型 |
| `/tools` | 列出可用工具 |
| `/clear` | 清空当前会话 |
| `/history` | 查看历史会话 |
| `/resume <id>` | 恢复某次会话 |
| `/approve` | 对当前危险操作确认放行 |

**技术**：`textual`（TUI 框架）+ `rich`（渲染）+ `prompt_toolkit`（输入补全）。

### 6.2 文本界面（Web）— Phase 3

**目标**：浏览器里的聊天式工作台，更适合多任务并行与产物预览。

- 聊天窗 + 流式输出（WebSocket）。
- 左侧"任务看板"：进行中 / 已完成 / 失败的任务。
- 右侧"产物预览"：代码、表格、图片、报告可直接查看/下载。
- 文件上传/拖拽，作为任务输入。
- 多会话管理、历史检索。

**技术**：`FastAPI` + `WebSocket`（后端）；`React` + `Vite`（前端）。

### 6.3 语音交互 — Phase 3/4

**目标**：免手操作，"动口不动手"。

- **语音输入（ASR）**：`silero-vad` 判断说完 → `faster-whisper` 转文本 → 走同一内核。
- **语音播报（TTS）**：结果用 `edge-tts` / `piper` 播报。
- **全双工**（进阶）：边听边说，支持打断。
- **场景**：开会间隙、做家务时，用语音让老黄牛"查个东西""跑个脚本"。

**注意**：语音层本质是 CLI/Web 的"输入输出适配器"，能力内核不变。

- [ ] 项目骨架、配置系统（`.env` + `config.yaml`）、日志

- [ ] ReAct 内核（思考—行动—观察循环，可中断、有审计日志）
- [ ] 工具注册表 + 首批工具：
  - 文件：`file_read` / `file_write` / `list_dir` / `grep`
  - 代码：`run_python`（沙箱）

- [ ] 会话持久化、`resume`、`/history`

**验收**：
- 一句话完成"清洗 Excel → 生成 Word 报告 → 存盘"。

- 长任务可中断、可恢复、可回放。

### Phase 3 — 多界面（文本 + 语音）

**目标**：从 CLI 扩展到 Web 文本界面与语音交互。

- [ ] Web 后端（FastAPI + WebSocket，复用内核）
- [ ] Web 前端（React：聊天 + 任务看板 + 产物预览 + 文件上传）
- [ ] 语音输入（VAD + ASR）
- [ ] 语音播报（TTS）
- [ ] 三界面共享协议与状态一致性

**验收**：
- 在浏览器里并行管理多个任务，产物可直接预览/下载。
- 用语音下达任务并听到结果播报。
- CLI / Web / 语音三种方式对同一任务表现一致。

### Phase 4 — 高级能力（探索）

**目标**：更强、更省、更聪明（可选，视需求推进）。

- [ ] 多智能体协作（规划者 / 执行者 / 审查者）

- [ ] 性能与成本优化（缓存、小模型分流、批量）

## 八、安全与风险

### 8.1 主要风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| 危险操作误伤 | 删除、覆盖、批量修改、执行未知命令 | 分级权限 + 强确认 + 路径白名单 + 沙箱 |
| 提示词注入 | 网页/文件内容诱导 Agent 执行恶意指令 | 外部内容只作"数据"不作"指令"；危险操作仍需确认 |
| 密钥泄露 | API Key 被写入日志/产物 | 密钥只从环境读取，日志脱敏，产物过滤 |
| 越权访问 | 读写工作目录之外的敏感文件 | 路径白名单 + 默认只在工作目录内操作 |
| 成本失控 | 长任务 token 消耗大 | token/时间预算 + 小模型分流 + 降级 + 中断 |
| 结果不可信 | LLM 幻觉导致错误结论 | 强制"带来源引用"；代码任务以"运行通过"为准 |
| 依赖/环境 | 跨平台差异、ffmpeg 等原生依赖 | 明确依赖清单、提供安装脚本、CI 校验 |

### 8.2 安全基线（自 Phase 1 起必须满足）

1. 所有工具调用有**审计日志**（谁、何时、何工具、何参数、何结果）。
2. `dangerous` 级操作**默认必须确认**。
3. 文件操作受**路径白名单**约束。
4. 代码/命令在**受限环境**执行。
5. API Key **不落盘、不进日志、不进产物**。

## 十、配置与部署

### 10.1 配置项（`config.yaml` 示例，示意）

```yaml
default_model: gpt-4o

routing:
  code: gpt-4o
  reasoning: claude
  multimodal: gemini
  batch_low_cost: gpt-4o-mini

fallback_chain: [gpt-4o, claude, gemini]

safety:
  workdir: ./
  allow_paths: ["./", "./data"]
  require_confirm:
    write: true
    execute: true
    dangerous: always

memory:
  short_term_max_tokens: 12000
  long_term_store: sqlite        # sqlite | supabase
  vector_store: lancedb          # 本地向量库

limits:
  max_steps: 25
  max_tokens_per_turn: 8000
  max_runtime_seconds: 600
```

```bash
# LLM 密钥（按需配置其一或多个）

GOOGLE_API_KEY=
```
