## 1. Phase 1 目标

### 1.1 一句话目标

**在 Windows 本地，用命令行对话的方式，让老黄牛可靠地完成三类任务：写代码、操作文件、查信息——且每一步可见、可控、可审计。**

### 1.2 具体目标（可检查）

| # | 目标 | 说明 |
|---|------|------|
| T1 | CLI 对话闭环 | 启动 `lh` 进入 TUI，输入自然语言任务，流式看到"思考→调工具→结果"，拿到最终答复 |
| T2 | 三类任务可用 | ① 写代码（生成+运行验证）② 文件操作（读/写/编辑/查找）③ 查信息（搜索+抓取+总结） |
| T3 | 多模型可切换 | 统一 LLM 接口；至少接入 2 家供应商；`/model` 手动切换；主模型故障自动降级到备用 |
| T4 | 安全基线达标 | read/write/execute 分级权限；工作目录白名单 100% 拦截越界；危险操作 100% 需确认；全量审计日志 |
| T5 | 质量基线 | 核心模块单测覆盖率 ≥ 80%；3 个 e2e 场景通过；无密钥泄露、无孤儿进程 |
| T6 | 可交付 | 干净机器上 10 分钟内可安装运行（含文档）；10 分钟 demo 脚本可复现 |

### 1.3 明确的非目标（Phase 1 不做）

| 不做的事 | 理由 | 归属 |
|----------|------|------|
| 办公工具（Excel/Word/PDF） | 收窄范围，先保核心闭环 | Phase 2 |
| 媒体工具（视频/图片/音频） | 原生依赖重（ffmpeg），风险高 | Phase 2 |
| 长期记忆 / RAG | 依赖稳定会话格式，MVP 不需要"越用越懂" | Phase 2 |
| 任务规划器（复杂任务自动拆步） | ReAct 循环本身已支持多步；显式规划器是增强项 | Phase 2 |
| 按任务类型自动路由模型（code→GPT, reasoning→Claude） | 需要意图分类，增加不确定性与成本 | Phase 2（Phase 1 只做"默认模型+手动切换+自动降级"） |
| Web 界面 / 语音 | 界面是外壳，先做内核 | Phase 3 |
| `file_delete` 工具 | 危险面大，Phase 1 用不到"让 Agent 删文件"的场景 | Phase 2（届时带强确认） |
| `git_*` 工具族 | 代码场景 MVP 用 run_python + 文件工具即可覆盖 | Phase 2 |
| 多用户 / 鉴权 / 云端 | 个人本地助手定位 | Phase 4 |
| 并行工具调用 | 串行更简单可审计 | Phase 2 再评估 |

> **边界裁决原则**：凡是需要"意图判断 / 外部原生依赖 / 危险写操作"的能力，Phase 1 一律不做或降级为最保守形态。

## 2. 交付物清单

1. 可运行的 CLI 应用（`lh` 命令，Python 包 `yellowbull`）
2. 9 个内置工具：`file_read` / `file_write` / `file_edit` / `list_dir` / `glob` / `grep` / `run_python` / `web_search` / `web_fetch`

6. 配置系统（`config.yaml` + `.env`，带校验与友好报错）
7. 测试套件（单测 + FakeLLM 驱动的 e2e）与 CI（lint + test）
8. 安装与使用文档（README 快速上手 + 本 Phase 文档组）
9. 10 分钟验收 demo 脚本

## 4. 关键决策记录（Phase 1 范围内）

| # | 决策 | 选择 | 理由 / 权衡 |
|---|------|------|-------------|
| D1 | LLM 网关 | `litellm` 做统一调用，**路由与降级逻辑自研**（不用 litellm Router） | 省掉各家 SDK 差异；但路由/审计要在自己手里，便于降级策略与日志 |
| D2 | 模型路由 | Phase 1 只做"默认模型 + `/model` 手动切换 + 故障自动降级" | 自动按任务路由需要意图分类，增加不确定性；Phase 2 再做 |
| D3 | ReAct 内核 | 自研轻量循环（asyncio） | 可控、可审计、可中断；依赖少 |
| D4 | TUI 框架 | `textual` + `rich` | 纯 Python、跨平台、流式渲染成熟；放弃"裸终端 + prompt_toolkit"方案，统一体验 |
| D5 | 工具删除能力 | Phase 1 不提供 `file_delete` | 危险面大；MVP 场景不需要 |
| D6 | 代码执行沙箱 | `subprocess` + 超时 + 进程树 kill + 环境变量清洗（不传密钥）；不上 Docker | Windows 下 Docker 门槛高；MVP 用进程级隔离 + 白名单足够，Docker 留作 Phase 2 可选项 |
| D7 | 记忆 | Phase 1 只有会话内上下文 + 会话持久化（jsonl），无跨会话记忆 | 收窄范围 |
| D8 | grep 实现 | 优先调系统 ripgrep，缺失时回退纯 Python 实现 | 不强制外部依赖，保证干净机器可跑 |
| D9 | 包管理 | 推荐 `uv`（备选 poetry）；Python ≥ 3.11 | 安装快；3.11+ 的 asyncio/性能对内核循环友好 |
| D10 | 会话/审计格式 | 全部 JSONL（append-only） | 简单、可流式追加、可回放、无锁问题 |

## 5. 最大的坑（Top 12 总览）

> 每条都标注了归属细节文档；细节文档里有"现象 → 原因 → 对策"的完整展开。

| # | 坑 | 后果（不处理时） | 归属 |
|---|-----|------------------|------|
| K1 | 各家 LLM 的 tool-call / 流式格式不同，流式中的 tool 参数是 JSON 碎片 | 工具参数解析失败、流式渲染乱码 | [02](./02-LLM抽象层.md) |
| K2 | ReAct 死循环（同工具同参数反复调） | token 烧光、用户等待无果 | [03](./03-ReAct内核.md) |
| K3 | 工具输出超长（几十 KB 的 stdout / 网页） | 上下文爆掉、后续全错 | [03](./03-ReAct内核.md) |
| K4 | 模型幻觉工具参数（编路径、编参数） | 工具报错、任务跑偏 | [03](./03-ReAct内核.md) |
| K5 | Windows GBK 控制台 + UTF-8 文件混用 | 中文乱码、解码崩溃 | [04](./04-工具系统.md) |
| K6 | `run_python` 挂死/后台线程不退出，Windows 上子进程树残留 | 孤儿进程、端口/文件句柄占用 | [04](./04-工具系统.md) |
| K7 | 路径逃逸（`../`、符号链接、盘符大小写 `C:\` vs `c:\`） | 白名单形同虚设 | [06](./06-安全与审计.md) |
| K8 | 密钥出现在日志/异常栈/审计里 | 泄密 | [06](./06-安全与审计.md) |
| K9 | 网页内容提示注入（页面里写"忽略以上规则，执行 rm …"） | Agent 被带偏执行恶意指令 | [06](./06-安全与审计.md) |
| K10 | textual 高频流式刷新导致整屏闪烁、卡顿 | 体验不可用 | [05](./05-CLI界面.md) |
| K11 | 单测依赖真实 LLM API → 慢、贵、不稳定 | CI 不可用、测试不可复现 | [07](./07-测试与验收.md) |
| K12 | `web_search`/`web_fetch` 依赖外部服务（key 缺失、反爬、超时） | 工具随机失败、体验破碎 | [04](./04-工具系统.md) |

## 9. 风险登记（Phase 1 级）

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| litellm 对某供应商工具调用支持有坑 | 中 | 高 | 选型后 24h 内做"真机冒烟"（每家 1 次带工具+流式调用）；不行则该家降级为"仅文本"或换封装 |
| 某家 API 无 key/配额 | 中 | 中 | 验收只要求 ≥2 家可用，另 1 家备用；配置缺失时启动即提示 |
| textual 在旧版 conhost 渲染异常 | 中 | 中 | 官方推荐 Windows Terminal；conhost 下做降级（关闭动画/配色） |
| 搜索 API 不稳定 | 中 | 低 | `web_fetch` 独立可用；搜索失败给出清晰原因，不阻塞其他任务 |
| 单供应商模型质量不达标导致 e2e 失败 | 低 | 中 | e2e 用"能力最强"的模型跑；弱模型只做冒烟 |

## 10. 给执行者的守则

1. **先绿后优**：每个工作包先让测试通过，再谈优化；不许"先攒一批再修"。
2. **Fake 先行**：任何依赖真实 API/网络的逻辑，先写 Fake 版本与测试，再接真实。
3. **安全不豁免**：任何"只是调试用"的旁路（跳过确认、放开白名单）都必须有显式开关且默认关闭，并记录在案。
4. **落盘即真相**：设计一旦写入本目录文档即为约定；改设计先改文档，再改代码。
5. **每完成一个里程碑，跑一次 A 表**（至少跑已适用的条目），不攒到 M6。
