# 04 · 工具系统（WP4）

> 工作包：工具契约、注册表、schema 校验、沙箱执行，以及 Phase 1 的 9 个内置工具逐个规格。
> 依赖：WP1（配置/日志）。被 WP3（内核）调用。
> 上游：[Phase 1 总览](./README.md)

## 1. 目标

- 工具即插件：统一的 `Tool` 契约 + `Registry`，新增工具不改内核。
- 9 个内置工具覆盖三大场景：文件（5）、代码执行（1）、Web（2）。
- 参数经 **schema 校验**后才执行；失败回喂结构化错误供模型自纠（K3-6）。
- 危险操作（write/execute）走安全门（WP6），工具本身不判权限。
- `run_python` 在沙箱内执行，超时可控、进程树可杀（K6/A10）。

## 2. 工具契约

```python
@dataclass
class Tool:
    name: str
    description: str
    parameters: dict          # JSON Schema（供 LLM + 校验）
    risk: RiskLevel           # read | write | execute
    func: Callable[["ToolArgs","ToolCtx"], "ToolResult"]

@dataclass
class ToolResult:
    ok: bool
    data: Any = None
    error: str | None = None
    truncated: bool = False
    artifact_path: str | None = None
```

**Registry**：
- `register(tool)` / `get(name)` / `all_specs()`（转成 LLM `ToolSpec`）。
- 启动自检：schema 合法、`name` 唯一、`func` 可调用；重复/非法直接启动失败（fail-fast）。

**执行流程（内核调用 `run(name, args)` 时）**：
1. schema 校验 `args` → 失败返回结构化错误（不执行）。
2. 安全门：`safety.gate(tool, args)` → `allow / need_confirm / deny`。
3. `need_confirm` → 内核发 `ToolConfirm` 事件等用户。
4. 执行 `func`，捕获异常 → 转 `ToolResult(ok=False, error=...)`。
5. 结果超长 → 截断 + 落 artifact（内核统一做，工具只管返回）。

## 3. 沙箱（run_python / run_shell）

- **进程级隔离**（Phase 1 不上 Docker，总览 D6）：
  - `subprocess` 启动，`cwd=workdir`，独立 `env`。
  - **env 清洗**：继承最小环境（PATH/系统变量），**剔除所有 `*_API_KEY`/`*_TOKEN`/`.env` 值**（联动 A6，K8）。
  - 超时：默认 `timeout=60s`（可配），到点 `terminate` → `kill`。
  - **Windows 进程树**：`CREATE_NEW_PROCESS_GROUP` + `taskkill /T /F <pid>` 保证子进程全灭（K6）。
  - 资源：限制 stdout/stderr 捕获大小（超限截断），避免内存爆。
- **不做**：网络隔离、CPU 配额（Phase 1 接受"用户自己的机器、用户发起"的前提；文档明示风险）。

## 4. 九个工具规格

> 统一：入参经 schema 校验；路径类参数都过 `safety.paths.resolve_in_workspace()`（白名单内才放行）。

### 文件类（risk=read，除 file_write/file_edit=write）

| 工具 | 入参 | 返回 | 说明/约束 |
|------|------|------|-----------|
| `file_read` | `path, offset?=1, limit?=2000` | 带行号文本 | 只读；超 `limit` 截断并提示"用 offset 续读" |
| `file_write` | `path, content` | 写入字节数 | **写/覆盖**，走确认；目录不存在则创建（白名单内） |
| `file_edit` | `path, old_str, new_str, replace_all?=false` | 替换次数 | `old_str` 必须**唯一匹配**（除非 replace_all）；找不到/多处 → 结构化错误 |
| `list_dir` | `path=".", depth?=1` | 树形列表 | 只列白名单内；忽略 `data/`、隐藏目录可配 |
| `glob` | `pattern, path="."` | 匹配文件列表 | 走 `pathlib.glob`；结果上限 500 条 |
| `grep` | `pattern, path=".", glob?=` | 命中行+文件 | 优先系统 `rg`，缺失回退纯 Python（总览 D8）；上限 200 行 |

### 代码类

| 工具 | 入参 | 返回 | 说明/约束 |
|------|------|------|-----------|
| `run_python` | `code? 或 file?, timeout?=60` | stdout/stderr/exit_code | **execute**，走确认；沙箱执行；输出截断落 artifact |

> `code` 与 `file` 二选一：给 `code` 则写临时文件再跑（临时文件在 `data/artifacts/tmp`，跑完可留供审查）。

### Web 类（risk=read）

| 工具 | 入参 | 返回 | 说明/约束 |
|------|------|------|-----------|
| `web_search` | `query, count?=5` | 标题+链接+摘要列表 | 用配置的搜索后端（Brave/Bing/SerpAPI）；**无 key → 返回结构化"未配置"错误**，不崩（K12） |
| `web_fetch` | `url, max_chars?=20000` | 正文文本 | `httpx` 抓取；只取 `text/html`→抽正文；超大小/非 HTML → 结构化错误；超时 20s |

## 5. 工具结果与截断

- 所有工具返回 `ToolResult`；内核统一做"超长截断 + 落 artifact"（避免每个工具各写一遍）。
- `data` 序列化规则：优先返回**字符串**（便于喂模型）；结构化数据转 JSON 字符串。
- 错误信息要"可自纠"：说清楚**哪个参数、为什么错、期望是什么**（供 K3-6 回喂）。

## 6. 边界

- 工具**不**判断权限/确认（安全门在内核+WP6）；工具**不**直接写审计（审计在内核）。
- 工具**不**访问 `data/audit`、`data/sessions`（防自我篡改，联动 WP6）。
- Phase 1 无 `file_delete`、无 `git_*`、无办公/媒体工具（总览非目标）。

## 7. 本包的坑

| # | 坑 | 现象 | 对策 |
|---|-----|------|------|
| K5 | GBK/UTF-8 混用 | 中文乱码、UnicodeDecodeError | 读文件先 `bytes`，按 `utf-8→gbk→latin-1` 顺序尝试解码；写统一 UTF-8 |
| K6 | `run_python` 挂死/子进程残留 | 孤儿进程、句柄占用 | 超时 terminate→kill + Windows `taskkill /T /F`；测试断言无残留（A10/A15） |
| K12 | 搜索 key 缺失/反爬/超时 | 工具随机失败 | 无 key 返回结构化"未配置"；`web_fetch` 独立可用；超时/非 HTML 给清晰错误 |
| K4-1 | 模型传了 schema 外参数 | 执行报错 | 严格 schema 校验 + 回喂"多余参数 X 非法" |
| K4-2 | `file_edit` old_str 匹配多处 | 误改 | 默认要求唯一匹配；多处 → 报错让模型加上下文 |
| K4-3 | 路径含 `../` 逃逸 | 越权 | `resolve_in_workspace()` 统一过白名单（WP6） |
| K4-4 | glob/grep 结果爆炸 | 上下文爆 | 结果条数上限（500/200）+ 截断提示 |
| K4-5 | 大文件 file_read | 内存/上下文爆 | `limit` 默认 2000 行 + 截断提示 offset |
| K4-6 | Windows 下 `rg` 不存在 | grep 失败 | 探测 `shutil.which("rg")`，缺失回退纯 Python 实现 |
| K4-7 | `web_fetch` 拿到 PDF/zip/二进制 | 解析崩溃 | 按 `Content-Type` 判断，非 `text/html` 直接结构化拒绝 |
| K4-8 | 工具返回 dict 里混入不可序列化对象 | 喂模型时 JSON 失败 | 统一 `json.dumps(ensure_ascii=False, default=str)` |

## 8. 验收（本包 DoD）

- [ ] 9 个工具各有正路径 + 至少 1 个错误路径单测（schema 校验、白名单、截断）。
- [ ] `run_python`：正常跑、超时被杀、Windows 下无孤儿进程（A10/A15 支撑）。
- [ ] `file_edit` 唯一匹配/多处/找不到 三态正确。
- [ ] `file_read` 大文件截断并提示 offset。
- [ ] `web_search` 无 key 时返回结构化"未配置"，不抛异常。
- [ ] `web_fetch` 对非 HTML/超大小/超时 返回清晰错误。
- [ ] `grep` 在"有 rg"和"无 rg"两种环境都能跑（CI 覆盖）。
- [ ] 路径逃逸（`../`、绝对路径出 workdir）100% 被拒（联动 A5）。
- [ ] 工具返回不含任何 key/敏感值（联动 A6）。
